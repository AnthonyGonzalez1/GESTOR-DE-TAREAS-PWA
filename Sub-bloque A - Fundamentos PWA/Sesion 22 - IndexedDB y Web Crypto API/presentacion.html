SECCIÓN 01

De Cache Storage a IndexedDB

Ni el caché HTTP ni la Cache Storage API saben responder preguntas sobre los datos que guardan.

ArchivosDatos estructurados
De Cache a IndexedDB · 1.1

Una pregunta que ninguno responde

"Dame todas las tareas con prioridad alta" — ni el caché HTTP ni la Cache Storage API saben responder eso sin descargar y revisar cada archivo uno por uno.

Guardan archivos

Pares Request → Response, o pares string → string. Se consultan por URL o clave exacta.

Nos falta esto

Una base de datos: objetos, índices, consultas por campo, y un cursor para recorrer o editar resultados.

SECCIÓN 02

Abrir y versionar una base de datos

Tres eventos, y un patrón para migrar el esquema sin perder datos.

createObjectStoreevent.oldVersion
Abrir y versionar · 2.1

indexedDB.open() y sus tres eventos

db.js
const peticion = indexedDB.open('gestor-tareas-db', 1);

peticion.onupgradeneeded = event => {
  const db = event.target.result;
  const store = db.createObjectStore('tareas', { keyPath: 'id', autoIncrement: true });
  store.createIndex('porPrioridad', 'prioridad', { unique: false });
};

peticion.onsuccess = event => { const db = event.target.result; };
peticion.onerror = event => console.error(event.target.error);
onupgradeneeded es el ÚNICO lugar donde se crean object stores e índices — solo se dispara cuando la DB no existe, o sube de versión.
Abrir y versionar · 2.2

Migrar el esquema: qué pasa cuando sube la versión

db.js (migración v1 → v2)
const peticion = indexedDB.open('gestor-tareas-db', 2);  // subimos de 1 a 2

peticion.onupgradeneeded = event => {
  const db = event.target.result;
  const tx = event.target.transaction;
  const version = event.oldVersion;  // versión desde la que se migra

  if (version < 1) {
    const store = db.createObjectStore('tareas', { keyPath: 'id', autoIncrement: true });
    store.createIndex('porPrioridad', 'prioridad', { unique: false });
  }
  if (version < 2) {
    const store = tx.objectStore('tareas');
    store.createIndex('porProyecto', 'proyectoId', { unique: false });
  }
};
event.oldVersion dice de dónde viene ese usuario. if (version < N) encadenado migra sin perder datos: crear algo que ya existe lanza un error.
SECCIÓN 03

Operaciones CRUD y cursores

Transacciones, operaciones básicas, y un cursor que también edita y borra.

add / put / getcursor.update()
CRUD y cursores · 3.1

Todo ocurre dentro de una transacción

db.transaction()

Abre una transacción: readonly o readwrite.

tx.objectStore()

Obtiene el store dentro de la transacción.

store.add()

Inserta; falla si la clave ya existe.

store.put()

Inserta o actualiza, sin fallar.

store.get()

Recupera un registro por su clave.

store.delete()

Elimina un registro por su clave.

store.getAll()

Recupera todos los registros.

store.count()

Cuenta registros sin traerlos.

Ninguna de estas devuelve una Promise — devuelven un IDBRequest. Se envuelven en Promise propia para usar async/await (o se usa una librería como idb).
CRUD y cursores · 3.2

Envolver IDBRequest en Promise

db.js
function agregarTarea(db, tarea) {
  return new Promise((resolve, reject) => {
    const tx = db.transaction('tareas', 'readwrite');
    const peticion = tx.objectStore('tareas').add(tarea);
    peticion.onsuccess = () => resolve(peticion.result);
    peticion.onerror = () => reject(peticion.error);
  });
}

// Uso, ahora con await:
const id = await agregarTarea(db, { titulo: 'Estudiar IndexedDB', prioridad: 'alta' });
CRUD y cursores · 3.3

Recorrer resultados con un cursor

db.js
const indice = store.index('porPrioridad');
const cursor = indice.openCursor(IDBKeyRange.only('alta'));

cursor.onsuccess = event => {
  const c = event.target.result;
  if (c) {
    resultado.push(c.value);
    c.continue();  // siguiente coincidencia
  } else {
    resolve(resultado);  // no hay más
  }
};
IDBKeyRange.only() limita el cursor a coincidencias exactas; también hay bound(), lowerBound() y upperBound() para rangos.
CRUD y cursores · 3.4

El cursor también edita y borra

db.js — cursor en modo escritura
const tx = db.transaction('tareas', 'readwrite');
const cursor = tx.objectStore('tareas').index('porPrioridad')
  .openCursor(IDBKeyRange.only('baja'));

cursor.onsuccess = event => {
  const c = event.target.result;
  if (!c) return;
  const registro = c.value;
  registro.hecha = true;
  c.update(registro);   // reescribe el registro actual, sin cerrar el cursor
  // c.delete();  también existe — borra el registro actual
  c.continue();
};
c.update(objeto) y c.delete() operan sobre el registro que el cursor tiene enfocado — sin su clave por separado.

Web Crypto: fundamentos · 4.1

crypto.subtle: promesas, solo HTTPS

crypto.subtleGenerar/derivar claves, cifrar, descifrar, calcular hashes.
Basada en promesasA diferencia de IndexedDB: se puede usar await directo.
Solo HTTPSIgual que los Service Workers (o localhost). Compatible con Web Workers.
Web Crypto: fundamentos · 4.2

SHA-256: una huella digital del dato

crypto.js
async function calcularHash(texto) {
  const datos = new TextEncoder().encode(texto);
  const buffer = await crypto.subtle.digest('SHA-256', datos);
  return Array.from(new Uint8Array(buffer))
    .map(b => b.toString(16).padStart(2, '0'))
    .join('');  // hash en hexadecimal
}

SHA-256 verifica integridad sin guardar el dato original: si el dato cambia un solo bit, el hash cambia por completo. AES-GCM (sección siguiente) es el algoritmo recomendado por MDN para cifrar; SHA-256, para verificar sin cifrar.
SECCIÓN 05

Derivar una clave real: PBKDF2

Una clave aleatoria se pierde al recargar. Una clave derivada de una contraseña se puede reconstruir siempre.

contraseña + salclave reproducible
Derivar una clave real · 5.1

Una clave aleatoria no sirve en la práctica

generateKey() — aleatoria

crypto.subtle.generateKey(...)
→ CryptoKey aleatoria

Perfecta para una demo de 5 minutos. Vive solo en memoria: si no se guarda en ningún lado, se pierde en cuanto se recarga la página — y con ella, todo lo cifrado.

✕ Inútil entre sesiones del usuario

PBKDF2 — derivada de una contraseña

contraseña + sal
→ deriveKey() ×100 000
→ CryptoKey reproducible

El usuario vuelve a escribir su contraseña en cualquier sesión futura, y — con la misma sal, guardada junto al dato cifrado — se reconstruye exactamente la misma clave.

✓ La misma clave, cada vez que hace falta
Derivar una clave real · 5.2

De contraseña a CryptoKey

crypto.js
async function derivarClaveDesdeContrasena(contrasena, sal) {
  const materialBase = await crypto.subtle.importKey(
    'raw', new TextEncoder().encode(contrasena),
    'PBKDF2', false, ['deriveKey']
  );

  return crypto.subtle.deriveKey(
    { name: 'PBKDF2', salt: sal, iterations: 100000, hash: 'SHA-256' },
    materialBase,
    { name: 'AES-GCM', length: 256 },
    false,  // no exportable: se re-deriva, no se guarda
    ['encrypt', 'decrypt']
  );
}

const sal = crypto.getRandomValues(new Uint8Array(16));
100 000 iteraciones: mínimo OWASP para PBKDF2-SHA256 — sube con el hardware. La sal se guarda junto al dato cifrado; la contraseña, nunca.
SECCIÓN 06

Cifrar y descifrar con AES-GCM

Con la clave ya derivada, falta el IV — y entender qué protege el cifrado, y qué no.

encrypt / decryptIV aleatorio
Cifrar con AES-GCM · 6.1

cifrarTexto() y descifrarTexto()

crypto.js
async function cifrarTexto(clave, texto) {
  const iv = crypto.getRandomValues(new Uint8Array(12));
  const datos = new TextEncoder().encode(texto);
  const cifrado = await crypto.subtle.encrypt({ name: 'AES-GCM', iv }, clave, datos);
  return { cifrado, iv };
}

async function descifrarTexto(clave, { cifrado, iv }) {
  const datos = await crypto.subtle.decrypt({ name: 'AES-GCM', iv }, clave, cifrado);
  return new TextDecoder().decode(datos);
}
El IV no es secreto, pero debe ser distinto cada vez que se cifra con la misma clave. Si la clave, el IV, o el cifrado no coinciden, decrypt() rechaza la promesa — así detecta manipulación.
Cifrar con AES-GCM · 6.2

Sobre guardar la clave

Una CryptoKey no exportable (como la derivada por PBKDF2) no se puede leer ni guardar directamente — solo se puede volver a derivar con la contraseña. Es intencional: cualquiera con acceso al navegador del usuario que encontrara una clave guardada podría descifrar todo sin conocer la contraseña.
El cifrado en el cliente protege contra fugas de la base de datos del servidor o de terceros que interceptan el tráfico — no contra alguien con acceso físico al dispositivo ya desbloqueado y a la contraseña en uso.

El Gestor de tareas, con datos cifrados

Cifrar solo lo sensible; dejar el resto plano y consultable con la clave derivada por contraseña.

título: planonotaPrivada: cifrada
Caso real · 7.1

Solo lo sensible se cifra

db.js
async function guardarTareaConNota(db, clave, tarea) {
  const { cifrado, iv } = await cifrarTexto(clave, tarea.notaPrivada);
  return agregarTarea(db, {
    titulo: tarea.titulo,          // plano: se busca y se filtra
    prioridad: tarea.prioridad,    // plano: tiene un índice
    notaCifrada: cifrado, notaIv: iv,  // cifrado: solo se lee de a uno
  });
}
El Gestor de tareas sigue filtrando por prioridad al instante con el índice de la sección 3 — la nota privada solo se descifra cuando el usuario abre esa tarea, y solo si conoce la contraseña.
Para verificarlo: DevTools → Application → IndexedDB → tareas. El campo notaCifrada debe verse como un ArrayBuffer ilegible, nunca como texto plano.

Resumen de la sesión

  • IndexedDB guarda objetos estructurados y consultables — a diferencia de Cache Storage y localStorage.
  • Object stores e índices se crean solo en onupgradeneeded; event.oldVersion permite migrar el esquema sin perder datos.
  • Un cursor recorre, actualiza (update()) o borra (delete()) registros uno a uno.
  • La Web Crypto API calcula hashes con SHA-256 y cifra con AES-GCM — basada en promesas, solo HTTPS.
  • PBKDF2 deriva una clave real y reproducible a partir de una contraseña y una sal — muy distinto de una clave aleatoria que se pierde al recargar.
  • El patrón real: cifrar solo lo sensible; el cifrado en el cliente protege de fugas de servidor o de red, no de acceso físico al dispositivo ya desbloqueado.
