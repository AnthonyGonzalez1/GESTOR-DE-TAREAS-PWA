¿Qué es una PWA?

Qué son las Progressive Web Apps, en qué se diferencian de una app nativa o híbrida, sus 8 características y sus 4 funcionalidades clave — el mapa completo de todo lo que vamos a construir en este bloque.

Objetivos de aprendizaje

  • ✓Definir qué es una Progressive Web App y explicar en qué se diferencia de una app nativa y de una app híbrida.
  • ✓Identificar las 8 características de una PWA (Discoverable, Responsive, Independent connectivity, App-like, Installable, Secure, Upgradable, Re-engageable) en una aplicación real.
  • ✓Explicar las 4 funcionalidades clave de una PWA (cacheo, ejecución en segundo plano, notificaciones push, experiencia offline) y qué tecnología hace posible cada una.
  • ✓Inspeccionar una PWA real en las DevTools del navegador y reconocer su manifest y su Service Worker ya funcionando.

2¿Qué es una Progressive Web App?

Una Progressive Web App (PWA) es una aplicación construida con tecnologías web tradicionales — HTML, CSS y JavaScript — que se ha mejorado para ofrecer una experiencia similar a la de una aplicación nativa en un teléfono o una tableta. No es un lenguaje nuevo ni un framework obligatorio: es un conjunto de técnicas que, aplicadas sobre una web normal, la hacen instalable, capaz de funcionar sin conexión, y capaz de reenganchar al usuario con notificaciones — combinando lo mejor de una app web (alcance, un solo código, actualizaciones instantáneas) con lo mejor de una app nativa (ícono en el dispositivo, funcionamiento offline, sensación de app real) [1].

Dato clave: el Gestor de tareas que construiste en las Sesiones 1 a 14 ya es una web app normal — funcional, pero no instalable ni disponible sin conexión. En este bloque vas a aprender, con ejemplos cortos, las técnicas que le faltan para ser una PWA, y luego las vas a aplicar de verdad, desde cero, en un proyecto nuevo.

3PWA vs. App Nativa vs. App Híbrida

Para entender qué resuelve una PWA, conviene compararla con las otras dos formas de construir aplicaciones móviles.

App Nativa: se construye con el lenguaje propio de cada plataforma (Kotlin/Java para Android, Swift para iOS) y se distribuye por una tienda de aplicaciones. Aprovecha al máximo el hardware del dispositivo y ofrece el mejor rendimiento posible — pero para llegar a Android y iOS hay que construir y mantener dos aplicaciones separadas, lo que incrementa el costo y el tiempo de desarrollo [2].

App Híbrida: se construye con tecnologías web, pero se empaqueta dentro de un contenedor nativo (un WebView) y se distribuye también por tienda de aplicaciones. Permite reutilizar un solo código base para varias plataformas y acceder a funciones del dispositivo mediante plugins, aunque su rendimiento y experiencia de usuario no llegan al nivel de una app nativa [3].

PWA: se construye con tecnologías web y se accede desde el navegador — sin pasar por ninguna tienda de aplicaciones. Un solo código sirve para cualquier dispositivo con un navegador moderno, el desarrollo es más rápido y económico, y aun así puede instalarse en la pantalla de inicio. Su límite está en el acceso a funcionalidades muy avanzadas del hardware, donde una app nativa sigue teniendo ventaja.

4Las 8 características de una PWA

Una PWA es adaptativa: siempre ofrece la mejor experiencia posible según la pantalla y el navegador del dispositivo, aunque no todos los navegadores soportan el mismo conjunto de funcionalidades [5]. Ocho características resumen lo que distingue a una PWA de una web común:

1
DiscoverableSe puede encontrar en los motores de búsqueda, como cualquier página web.
2
ResponsiveSe adapta correctamente a cualquier tamaño de pantalla.
3
Independent connectivityFunciona sin conexión o con conectividad limitada, gracias al Service Worker.
4
App-likeSe ve y se comporta como una aplicación nativa, no como una página web tradicional.
5
InstallableSe instala directamente desde el navegador, sin pasar por una tienda de aplicaciones.
6
SecureSe sirve siempre por HTTPS, protegiendo la integridad de sus datos.
7
UpgradableSe actualiza sola, sin interrumpir la experiencia del usuario.
8
Re-engageablePuede enviar notificaciones push para mantener al usuario interesado.

Las 8 características de una PWA. Fuente: elaboración propia, a partir de [5].

Dato clave: ninguna de estas 8 características depende de un framework — todas se logran con APIs estándar del navegador (Web App Manifest, Service Worker, HTTPS, Notifications API), que iremos viendo una por una en las próximas sesiones.

5Las 4 funcionalidades clave

Estas 8 características se apoyan en 4 funcionalidades concretas — el "cómo" detrás del "qué":

  • Cacheo de recursos: la interfaz de usuario y otros elementos esenciales se almacenan en el dispositivo, permitiendo una carga rápida y una navegación fluida incluso con mala conexión. (Sesiones 18-19.)
  • Ejecución en segundo plano: el Service Worker puede sincronizar datos y gestionar notificaciones sin que el usuario tenga la aplicación abierta. (Sesión 17 y Sesión 20.)
  • Notificaciones push: la aplicación recibe alertas del servidor en tiempo real, manteniendo al usuario informado incluso cuando no la está usando. (Sesión 20.)
  • Experiencia offline: la aplicación funciona sin conexión y sincroniza los datos automáticamente cuando la conectividad se restablece. (Sesiones 18-20.)

Todas estas funcionalidades comparten una misma pieza central, que vamos a conocer a fondo en la Sesión 17: el Service Worker — un script que el navegador ejecuta por separado de la página, y que actúa como intermediario entre la aplicación y la red.

6Caso real: inspeccionando una PWA

La forma más rápida de reconocer estas ideas es verlas funcionando. Aplicaciones como Twitter (X) Lite o Starbucks son PWA conocidas: se abren desde el navegador, se pueden instalar en la pantalla de inicio, y siguen mostrando algo (aunque sea un mensaje de "sin conexión" bien diseñado) incluso sin internet.

Piensa en tres aplicaciones que uses habitualmente en tu teléfono. Resumen de la sesión

  • Una PWA es una web app mejorada con técnicas que la hacen instalable, offline y re-enganchable — sin dejar de ser, en el fondo, HTML, CSS y JavaScript.
  • Frente a una app nativa (mejor rendimiento, más cara) y una app híbrida (intermedia), la PWA prioriza alcance, velocidad de desarrollo y un solo código para todos los dispositivos.
  • Las 8 características (Discoverable, Responsive, Independent connectivity, App-like, Installable, Secure, Upgradable, Re-engageable) son el criterio para reconocer una PWA.
  • Las 4 funcionalidades (cacheo, segundo plano, notificaciones push, offline) son el "cómo" — y casi todas dependen de una misma pieza: el Service Worker.
  • Estas técnicas no son exclusivas de un proyecto — se aplican encima de cualquier web app, sesión a sesión, hasta convertirla en una PWA completa.
