SECCIÓN 01

Dos mecanismos de caché

"Caché" en el navegador en realidad son dos sistemas completamente independientes.

SECCIÓN 02

El caché HTTP tradicional

Existe desde mucho antes que las PWA — lo controla el servidor con encabezados.

Cache-ControlETagLast-Modified
Caché HTTP · 2.1

Tres encabezados que lo controlan

Cache-Control

El principal: max-age=3600 (reutilizar 1h) o no-store (nunca guardar).

ETag

Huella digital del recurso: pregunta "¿cambió?" sin descargarlo completo.

Last-Modified

Similar a ETag, basado en la fecha de la última modificación.

Funciona igual con o sin Service Worker — es responsabilidad del navegador y del servidor, no de la aplicación.
SECCIÓN 03

La interfaz Cache

Dos objetos globales, ocho operaciones que cubren casi todo lo que se necesita.

cachesCache
La interfaz Cache · 3.1

Las operaciones principales

caches.open()

Abre o crea un caché con nombre.

cache.addAll()

Hace fetch y guarda cada URL de la lista.

cache.put()

Guarda una respuesta específica.

cache.match()

Busca una respuesta guardada.

cache.delete()

Elimina una entrada del caché.

cache.keys()

Lista las peticiones guardadas.

caches.keys()

Lista los nombres de todos los cachés.

caches.delete()

Elimina un caché completo.

SECCIÓN 04

Cache Storage en la práctica

put() para guardar, match() para recuperar — la base de todo lo que viene.

put() + match()
En la práctica · 4.1

Guardar y recuperar, a mano

sw.js (fragmento)
async function guardarManual() {
  const cache = await caches.open('gestor-tareas-v1');
  const respuesta = await fetch('/css/estilos.css');
  await cache.put('/css/estilos.css', respuesta);
}

async function buscarEnCache(peticion) {
  const cache = await caches.open('gestor-tareas-v1');
  return await cache.match(peticion);
}
Esta pareja es la base de las 5 estrategias de caché de la Sesión 19.
SECCIÓN 05

Gestión de versiones

Cambiar el nombre del caché deja huérfano al anterior — hay que limpiarlo a mano.

v1 → v2activate
Versiones · 5.1

Limpiar cachés antiguos en activate

sw.js (fragmento)
const CACHE_ACTUAL = 'gestor-tareas-v2';

self.addEventListener('activate', event => {
  event.waitUntil(
    caches.keys().then(nombres =>
      Promise.all(
        nombres.filter(n => n !== CACHE_ACTUAL)
               .map(n => caches.delete(n))
      )
    )
  );
});
SECCIÓN 06

Caso real: el sw.js actualizado

Instalación, limpieza de versiones y fetch, juntos — y cómo verificarlo.

sw.js completo
Caso real · 6.1

El sw.js completo

sw.js
const CACHE_ACTUAL = 'gestor-tareas-v2';
const CORE_ASSETS = ['/index.html', '/css/estilos.css', '/js/app.js', '/manifest.json'];

self.addEventListener('install', event => {
  event.waitUntil(caches.open(CACHE_ACTUAL).then(cache => cache.addAll(CORE_ASSETS)));
});

self.addEventListener('activate', event => {
  event.waitUntil(
    caches.keys().then(n => Promise.all(n.filter(x => x!==CACHE_ACTUAL).map(x => caches.delete(x))))
      .then(() => self.clients.claim())
  );
});

self.addEventListener('fetch', event => {
  event.respondWith(fetch(event.request));
});

Resumen de la lección

  • El caché HTTP lo controla el servidor con encabezados; funciona con o sin Service Worker.
  • La Cache Storage API es independiente, controlada por JS, y requiere un Service Worker activo.
  • Operaciones clave: open(), put()/addAll(), match(), delete(), keys().
  • put() + match() son la base de las estrategias de caché de la Sesión 20.
  • Versionar el nombre del caché y limpiarlo en activate evita acumular espacio innecesario.
