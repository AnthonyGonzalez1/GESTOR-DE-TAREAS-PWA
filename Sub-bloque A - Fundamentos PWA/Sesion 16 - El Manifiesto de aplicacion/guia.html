El Manifiesto de aplicación

El archivo JSON que le dice al navegador y al sistema operativo cómo debe verse y comportarse tu PWA una vez instalada: su nombre, sus íconos, sus colores, su modo de visualización — y qué hace falta para que el navegador la ofrezca instalar.

Objetivos de aprendizaje

  • ✓Explicar qué es el Web App Manifest y qué papel cumple en la integración de una PWA con el navegador y el sistema operativo.
  • ✓Escribir un manifest.json completo, con las propiedades correctas para el nombre, los colores, la orientación y el modo de visualización.
  • ✓Distinguir los cuatro modos de display y elegir el correcto según el tipo de aplicación.
  • ✓Preparar íconos en los tamaños y con el purpose (any / maskable) que el navegador exige para instalar.
  • ✓Vincular el manifest a un documento HTML y verificar, en DevTools, que cumple los criterios de instalabilidad.

  • Descargar .zipProyecto base — Gestor de Tareas. El mismo proyecto cerrado en la Sesión 14, sin PWA todavía: es donde vas a agregar el manifest.json de hoy.

Hoy dejamos de hablar de él en abstracto y escribimos el nuestro — el primer archivo nuevo que el Gestor de tareas recibe en este bloque.

Dato clave: hoy es la primera sesión del bloque en la que escribimos código de verdad. Todo lo anterior (Sesión 15) fue panorama; a partir de hoy, cada sesión agrega una pieza concreta y funcional al proyecto.

2¿Qué es el manifest.json?

El manifiesto de aplicación (manifest.json) es un archivo JSON esencial para la integración de una PWA con el navegador y con el sistema operativo. Define su apariencia y su comportamiento una vez instalada en el dispositivo del usuario, permitiendo una experiencia más fluida y más parecida a la de una aplicación nativa [1][2].

En la práctica, es el archivo que responde preguntas muy concretas: ¿cómo se llama la app? ¿qué ícono usa? ¿de qué color es la barra de título cuando está instalada? ¿se abre como una ventana propia o como una pestaña más del navegador? Sin manifest, el navegador no tiene forma de saber que tu web "quiere" comportarse como una aplicación instalable — es, junto al Service Worker (Sesión 17), uno de los dos requisitos técnicos de toda PWA.

3Anatomía del manifest.json

El manifest es un objeto JSON plano: un conjunto de propiedades clave-valor. Estas son las que usamos en el Gestor de tareas:

nameNombre completo. Aparece en el diálogo de instalación y en la pantalla de carga (splash screen)."Gestor de Tareas — Electiva PWA"
short_nameNombre corto. Aparece bajo el ícono en la pantalla de inicio, donde el espacio es limitado."Tareas"
descriptionDescripción breve de la aplicación, usada por el navegador y algunas tiendas."Gestiona tus tareas, incluso sin conexión."
start_urlLa URL que se abre cuando el usuario lanza la app ya instalada."/index.html"
scopeQué parte del sitio se considera "dentro" de la app (fuera de scope, se abre el navegador normal)."/"

4Los modos de display

La propiedad display es, probablemente, la que más cambia cómo se siente la app instalada. El navegador ofrece cuatro modos, de más inmersivo a menos inmersivo:

fullscreen

Usa toda el área de la pantalla, sin ninguna interfaz del navegador ni del sistema operativo (ni siquiera la barra de estado). Se usa casi exclusivamente en juegos.

standalone

Se ve y se siente como una app nativa: sin barra de direcciones, con su propio ícono en la barra de tareas o el conmutador de apps. Es el modo más común para una PWA — el que usa el Gestor de tareas.

minimal-ui

Similar a standalone, pero conserva un mínimo de controles de navegación del navegador (por ejemplo, atrás/adelante). Útil cuando la app necesita que el usuario pueda "retroceder" con facilidad.

browser

Se abre como una pestaña normal del navegador, con toda su interfaz visible. Es el comportamiento por defecto si no se especifica display — es decir, si se omite esta propiedad, la app no se ve como instalada aunque técnicamente lo esté.

Dato clave: si display se omite o vale "browser", Chrome no la considera "app-like" y puede no ofrecer instalarla — esta propiedad es, en la práctica, obligatoria para una PWA real.

5Los íconos: tamaños y maskable icons

La propiedad icons es un arreglo de objetos, cada uno con src (la ruta del archivo), sizes (el tamaño, en píxeles) y type (el formato MIME). Chrome exige, como mínimo, un ícono de 192×192 y uno de 512×512 para ofrecer la instalación — el primero se usa en la pantalla de inicio, el segundo en el splash screen y en contextos de mayor resolución.

purposeQué significaCuándo usarlo
"any" (por defecto)El sistema operativo puede recortar el ícono a la forma que use (círculo, cuadrado redondeado, squircle) sin ninguna garantía sobre qué queda dentro.Íconos simples, ya centrados, sin detalle cerca del borde.
"maskable"El ícono se diseñó con una zona segura central (aprox. el 80% del lienzo): el sistema puede recortar libremente fuera de esa zona sin cortar contenido importante.Cuando se quiere que el ícono se vea bien recortado en cualquier forma del sistema operativo — la práctica recomendada hoy en día.

Los dos valores de purpose para un ícono de manifest. Fuente: adaptado de "Maskable icon," web.dev [4].

6Vinculando el manifest y criterios de instalabilidad

Tener un manifest.json no basta: hay que enlazarlo desde el HTML, en el <head>, y acompañarlo de un <meta> de color de tema para navegadores que lo leen por separado:

index.html
<head>
  <!-- ...meta charset, viewport, title... -->
  <link rel="manifest" href="manifest.json">
  <meta name="theme-color" content="#1A1A1A">
</head>

Con eso enlazado, el navegador evalúa si la app cumple los criterios de instalabilidad. En Chrome, hoy en día, son básicamente cinco:

  1. Servirse por HTTPS (o desde localhost en desarrollo).
  2. Tener un manifest enlazado, válido, con al menos name o short_name.
  3. Incluir al menos un ícono de 192×192 y uno de 512×512.
  4. Definir start_url y un display de standalone, fullscreen o minimal-ui.
  5. Tener un Service Worker registrado, con al menos un manejador del evento fetch — la pieza que construimos en la Sesión 17.
Adelanto: hasta que no tengamos Service Worker (próxima sesión), el manifest de hoy cumple 4 de los 5 criterios. Chrome no ofrecerá instalar el Gestor de tareas todavía — pero ya podemos verificar en DevTools que los primeros cuatro están en verde. El navegador también dispara un evento, beforeinstallprompt, que una app puede capturar para mostrar su propio botón "Instalar" en vez de esperar al ícono automático de la barra de direcciones — lo usaremos más adelante en el bloque.

7Caso real: el manifest.json del Gestor de tareas

Juntando todo lo anterior, este es el manifest.json completo que agregamos hoy al proyecto:

manifest.json
{
  "name": "Gestor de Tareas — Electiva PWA",
  "short_name": "Tareas",
  "description": "Gestiona tus tareas, incluso sin conexión.",
  "start_url": "/index.html",
  "scope": "/",
  "display": "standalone",
  "orientation": "portrait",
  "theme_color": "#1A1A1A",
  "background_color": "#FFCC29",
  "lang": "es",
  "dir": "ltr",
  "icons": [
    {
      "src": "icons/icon-192.png",
      "sizes": "192x192",
      "type": "image/png",
      "purpose": "any"
    },
    {
      "src": "icons/icon-512-maskable.png",
      "sizes": "512x512",
      "type": "image/png",
      "purpose": "maskable"
    }
  ]
}

Para verificarlo: F12 → pestaña Application → sección Manifest. Chrome muestra cada propiedad interpretada, una vista previa del ícono en distintas formas de recorte, y — muy importante — una lista de "Installability" con los criterios que faltan por cumplir (hoy nos va a marcar el Service Worker en rojo; eso es exactamente lo esperado).

Resumen de la sesión

  • El manifest.json es el archivo JSON que le dice al navegador y al sistema operativo cómo debe verse y comportarse tu PWA instalada.
  • Propiedades clave: name/short_name, start_url, scope, display, theme_color/background_color, icons.
