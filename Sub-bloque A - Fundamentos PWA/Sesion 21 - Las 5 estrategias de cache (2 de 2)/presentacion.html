SECCIÓN 01

Network First

Intenta la red primero; si falla, usa el caché como respaldo.

Red → Caché
Network First · 1.1

Caché respondecomo respaldo
sw.js (fragmento)
function networkFirst(peticion) {
  return fetch(peticion)
    .then(respuesta => {
      const clon = respuesta.clone();
      caches.open(CACHE_ACTUAL).then(cache => cache.put(peticion, clon));
      return respuesta;
    })
    .catch(() => caches.match(peticion));
}
Simetría casi exacta con Cache First: el mismo patrón "intenta A, si falla usa B", con A y B invertidos.
SECCIÓN 02

Stale-While-Revalidate

Responde de inmediato desde caché, y actualiza en segundo plano.

Caché instantáneo+ red en paralelo
Stale-While-Revalidate · 2.1

Rápido ahora, fresco después

1
Página pideal Service Worker
→
2-3
SW respondede inmediato con el caché ("stale")
→
4-5
En paralelo:pide a la red y actualiza el caché
sw.js (fragmento)
function staleWhileRevalidate(peticion) {
  return caches.open(CACHE_ACTUAL).then(cache =>
    cache.match(peticion).then(enCache => {
      const actualizacion = fetch(peticion).then(respuesta => {
        cache.put(peticion, respuesta.clone());
        return respuesta;
      });
      return enCache || actualizacion;
    })
  );
}
La línea clave: enCache || actualizacion. Si había algo en caché, se devuelve ya; la petición a la red sigue en curso y actualiza el caché para la próxima vez.

SECCIÓN 03

Combinando estrategias por ruta

Un Service Worker real casi nunca usa una sola estrategia para todo.

/icons/ → Cache First/api/ → Network First
Caso real · 3.1

El Gestor de tareas, enrutado

sw.js
self.addEventListener('fetch', event => {
  const url = new URL(event.request.url);

  if (url.pathname.startsWith('/icons/')) {
    // Íconos: rara vez cambian → Cache First
    event.respondWith(cacheFirst(event.request));
  } else if (url.pathname.startsWith('/api/')) {
    // Datos de la API: deben verse al día → Network First
    event.respondWith(networkFirst(event.request));
  } else {
    // HTML, CSS, JS del shell: rápido, y se actualiza solo → Stale-While-Revalidate
    event.respondWith(staleWhileRevalidate(event.request));
  }
});
El proyecto real del curso no tiene todavía una ruta /api/ — queda ahí como ejemplo de cómo se vería si la tuviera. Verificable en DevTools → Network (filtro Service Worker) + modo offline.

Resumen de la sesión

  • Network First intenta la red primero y usa el caché como respaldo — es la simétrica de Cache First.
  • Stale-While-Revalidate responde de inmediato desde caché mientras actualiza en segundo plano.
  • Ya con las 5 completas: cubren desde lo totalmente inmutable hasta lo siempre-fresco.
  • Un Service Worker real casi siempre combina varias estrategias, enrutando por el path de la petición.
  • DevTools (Network + modo offline) permite verificar, sin adivinar, de dónde vino realmente cada respuesta.
