SECCIÓN 01

Qué miden los sensores de movimiento

El navegador no te entrega los chips en crudo: los mezcla y expone dos eventos de window.

deviceorientationdevicemotion
Sensores · 1.1

Dos eventos: inclinación y movimiento

Un teléfono lleva un acelerómetro (cuánto se acelera en cada eje), un giroscopio (cuánto rota) y, en muchos modelos, un magnetómetro (hacia dónde queda el norte magnético).

deviceorientation

Cómo está inclinado el dispositivo. Entrega tres ángulos en grados: alpha, beta y gamma.

devicemotion

Cómo se está moviendo. Entrega acceleration, accelerationIncludingGravity (ambas en m/s²), rotationRate (grados/s) e interval (ms entre lecturas).

accelerationIncludingGravity incluye la gravedad. Con el teléfono quieto sobre la mesa, la suma de sus tres ejes da aproximadamente 9,81 m/s² apuntando hacia abajo. Eso es lo que usaremos para detectar una sacudida: no el valor de un eje, sino cuánto se aleja el total de la gravedad.
Sensores · 1.2

alpha, beta y gamma: ejes y rangos

ÁnguloEjeRangoCómo sentirlo
alphaz (perpendicular a la pantalla)0 a 360Girar el teléfono sobre una mesa, como una brújula
betax−180 a 180Inclinarlo hacia adelante o hacia atrás
gammay−90 a 90Inclinarlo hacia la izquierda o la derecha

Rangos y ejes según MDN. Existe además deviceorientationabsolute, referido a la Tierra en vez de a la posición de arranque; hoy no lo usamos.

SECCIÓN 02

Permiso y contexto seguro (con una trampa de iOS)

Los eventos de orientación solo se entregan en contexto seguro (HTTPS o localhost), igual que cámara y ubicación.

HTTPS o localhostrequestPermission
Permiso · 2.1

iOS exige pedir permiso explícito

iOS (Safari) exige pedir permiso explícito con DeviceOrientationEvent.requestPermission() (y DeviceMotionEvent.requestPermission() para movimiento). Ese método:

  • solo existe en los navegadores que lo exigen — en Chrome para escritorio, typeof DeviceOrientationEvent.requestPermission vale "undefined" (lo medí), así que hay que comprobar antes de llamarlo;
  • requiere un gesto del usuario (un clic); sin él, la promesa se rechaza con NotAllowedError;
  • devuelve "granted" o "denied";
  • MDN lo marca como de disponibilidad limitada: no es universal.
Permiso · 2.2

Comprobar antes de llamar

sensores.js
export async function pedirPermisoSensores() {
  if (!("DeviceMotionEvent" in window)) return "no-soportado";
  if (typeof DeviceMotionEvent.requestPermission === "function") {
    try {
      return await DeviceMotionEvent.requestPermission();   // "granted" | "denied"
    } catch {
      return "denied";           // p. ej. NotAllowedError por no venir de un clic
    }
  }
  return "no-necesario";         // Android/Chromium: el permiso es implícito
}
Lo que no pude verificar aquí: la rama de iOS. Este entorno no tiene un iPhone, así que requestPermission está escrito según la documentación de MDN, no probado. La Actividad 4 te pide probarlo en un iPhone o un iPad si tienes acceso, y reportar qué pasó.
SECCIÓN 03

¿Hay sensores de verdad?

Un computador de escritorio tiene DeviceOrientationEvent (el objeto existe), pero no tiene sensores.

Un evento con nullTiempo máximo
Sensores reales · 3.1

Esperar una lectura con valores reales

Lo que hace Chromium de escritorio, medido en esta sesión: dispara un solo evento con alpha, beta y gamma en null y accelerationIncludingGravity.x en null, y después silencio. Por eso preguntar "¿existe la API?" no sirve: hay que esperar una lectura con valores reales, con un tiempo máximo.
sensores.js
export function hayLecturasReales(timeoutMs = 1000) {
  return new Promise((resolve) => {
    const alRecibir = (e) => {
      const a = e.accelerationIncludingGravity;
      if (a && a.x !== null) { limpiar(); resolve(true); }
    };
    const limpiar = () => {
      window.removeEventListener("devicemotion", alRecibir);
      clearTimeout(t);
    };
    const t = setTimeout(() => { limpiar(); resolve(false); }, timeoutMs);
    window.addEventListener("devicemotion", alRecibir);
  });
}
SECCIÓN 04

Leer la orientación sin saturar la interfaz

Un sensor real dispara decenas de eventos por segundo. Si cada uno repinta algo, la interfaz se arrastra.

Frecuencia limitadaFunción para apagar
Orientación · 4.1

Como máximo 10 avisos por segundo

sensores.js
export function escucharOrientacion(callback, intervaloMs = 100) {
  let ultimo = 0;
  const manejador = (e) => {
    const ahora = performance.now();
    if (ahora - ultimo < intervaloMs) return;
    ultimo = ahora;
    if (e.beta === null) return;                       // sin sensor
    callback({ alfa: e.alpha, beta: e.beta, gamma: e.gamma });
  };
  window.addEventListener("deviceorientation", manejador);
  return () => window.removeEventListener("deviceorientation", manejador);
}
La solución habitual es limitar la frecuencia con la hora de la última lectura aceptada: aquí, como máximo 10 avisos por segundo (cada 100 ms). Y se devuelve una función para dejar de escuchar: un sensor activo gasta batería, así que hay que poder apagarlo.
SECCIÓN 05

Detectar una sacudida

Una sacudida es una aceleración fuerte y breve. Tres decisiones de diseño: umbral, enfriamiento y devolver cuánto.

UmbralEnfriamientoDesviación
Sacudida · 5.1

Cuánto se aleja el total de la gravedad

Con el teléfono quieto, la magnitud Math.hypot(x, y, z) de accelerationIncludingGravity ronda 9,81; al sacudirlo se dispara muy por encima (o por debajo, en el instante de frenar). Así que miramos cuánto se aleja de la gravedad: la desviación.

Umbral

A partir de qué desviación cuenta como sacudida. Con 12 m/s², caminar o dejar caer el teléfono suavemente no dispara; sacudirlo con ganas sí. Es un punto de partida: se ajusta probando con hardware real (Actividad 2).

Enfriamiento

Una sola sacudida produce docenas de lecturas por encima del umbral. Sin una pausa (aquí 1 segundo) se dispararía la acción veinte veces.

Devolver cuánto

El callback recibe la desviación medida, útil para depurar y calibrar.

Sacudida · 5.2

detectarSacudida: umbral y enfriamiento

sensores.js
export function detectarSacudida(onSacudida, { umbral = 12, enfriamientoMs = 1000 } = {}) {
  const GRAVEDAD = 9.81;
  let ultimaSacudida = 0;
  const manejador = (e) => {
    const a = e.accelerationIncludingGravity;
    if (!a || a.x === null) return;
    const magnitud = Math.hypot(a.x, a.y, a.z);
    const desviacion = Math.abs(magnitud - GRAVEDAD);
    const ahora = performance.now();
    if (desviacion > umbral && ahora - ultimaSacudida > enfriamientoMs) {
      ultimaSacudida = ahora;
      onSacudida(Math.round(desviacion * 10) / 10);
    }
  };
  window.addEventListener("devicemotion", manejador);
  return () => window.removeEventListener("devicemotion", manejador);
}
SECCIÓN 06

Mejora progresiva: nunca la única forma

Un computador no se puede sacudir, y alguien con movilidad reducida puede no querer hacerlo.

Botón visibleSensores como atajo
Mejora progresiva · 6.1

Dos caminos para la misma acción

↩ Deshacer eliminación

Un botón visible que funciona en cualquier dispositivo.

Los sensores

Un atajo adicional: nunca la única forma.

El flujo del botón "📳 Activar agitar para deshacer" es:

  1. El usuario pulsa el botón (así el permiso de iOS se pide dentro de un clic).
  2. Si el permiso es denied → mensaje claro, y el botón "Deshacer" sigue ahí.
  3. Si no hay lecturas reales (portátil) → mensaje claro, y el botón "Deshacer" sigue ahí.
  4. Si todo va bien → se escucha la sacudida y la orientación (para mostrar la inclinación en pantalla), y un segundo clic apaga los sensores.
Mejora progresiva · 6.2

La acción es la misma, venga del botón o de la sacudida

  • Al eliminar una tarea se guarda copia en ultimaEliminada.
  • deshacerEliminacion() la vuelve a insertar en IndexedDB, que le asigna un id nuevo — por eso se descarta el id viejo.
Un detalle que importa: el índice porTitulo de la Sesión 22 es único, así que reinsertar un título que otra tarea ya ocupa fallaría. En este flujo no ocurre porque se restaura la última eliminada antes de cualquier otra operación, pero es un buen caso límite para probar (Actividad 3).

Qué demuestra — y sus límites honestos

Qué demuestra: (1) sin sensores, la app lo detecta y manda al botón de respaldo, que funciona; (2) con una orientación simulada de 30°, el indicador muestra β 30°; (3) una aceleración simulada de (25, 10, 9,81) tiene magnitud ≈ 28,7 m/s², una desviación de ≈ 18,9 sobre la gravedad — por encima del umbral de 12 —, y la tarea eliminada reaparece. Cero errores en consola.
Límites honestos: son sensores simulados, sin ruido ni deriva. El umbral de 12 m/s² salió de la teoría y de esta simulación, no de un teléfono real; la forma de comprobar que sirve es la Actividad 2. Tampoco se probó la rama de iOS (sección 2).

Resumen de la sesión

  • deviceorientation entrega la inclinación en tres ángulos (alpha 0–360, beta −180–180, gamma −90–90); devicemotion entrega aceleración (con y sin gravedad) y velocidad de rotación.
  • Hace falta contexto seguro; en iOS, además, un requestPermission() dentro de un clic, que no existe en otros navegadores y por eso se comprueba antes de llamar.
  • Un computador dispara un evento con todo en null: se detectan sensores reales esperando una lectura con valores, con un tiempo máximo.
  • Se limita la frecuencia de lectura y se devuelve una función para apagar el sensor.
  • La sacudida se detecta por la desviación de la magnitud respecto a 9,81 m/s², con umbral y enfriamiento; el umbral correcto sale de medir, no de suponer.
  • Los sensores son mejora progresiva: siempre hay un botón que hace lo mismo.
