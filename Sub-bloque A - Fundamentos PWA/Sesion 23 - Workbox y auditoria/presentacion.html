SECCIÓN 02

Workbox: qué es y sus módulos

Una librería que encapsula Service Worker y Cache Storage — presente en el 54% de los sitios móviles con service workers.

routingstrategiesprecaching
Workbox: módulos · 2.1

Cinco módulos, el mismo trabajo de las Sesiones 17-21

workbox-routing

Enruta las solicitudes interceptadas por el service worker — el equivalente a los if/else por path de la Sesión 21.

workbox-strategies

CacheFirst, NetworkFirst, StaleWhileRevalidate ya implementadas — las mismas estrategias de las Sesiones 20-21.

workbox-precaching

Calcula un hash del contenido de cada archivo y genera la lista de precaché automáticamente — nunca se escribe a mano.

workbox-expiration

Expira entradas por antigüedad (maxAgeSeconds) o cantidad (maxEntries) — algo que cacheFirst() manual nunca hizo.

workbox-window

Simplifica el registro y la actualización del service worker desde la ventana del navegador [2].

Workbox: módulos · 2.2

El enrutamiento de la Sesión 21, con Workbox

sw.js (con Workbox, escrito a mano)
import { registerRoute } from 'workbox-routing';
import { CacheFirst, NetworkFirst, StaleWhileRevalidate } from 'workbox-strategies';
import { ExpirationPlugin } from 'workbox-expiration';

registerRoute(
  ({ url }) => url.pathname.startsWith('/icons/'),
  new CacheFirst({
    cacheName: 'imagenes',
    plugins: [new ExpirationPlugin({ maxEntries: 60, maxAgeSeconds: 30*24*60*60 })]
  })
);
registerRoute(({ url }) => url.pathname.startsWith('/api/'),
  new NetworkFirst({ cacheName: 'api-tareas' }));
registerRoute(({ request }) => ['document','script','style'].includes(request.destination),
  new StaleWhileRevalidate({ cacheName: 'shell' }));
Tres rutas, tres estrategias — sin clonar respuestas ni abrir el caché a mano. Esto todavía se escribe a mano; en la sección 4, ni esto se escribe.

La configuración, sobre el checkpoint de la Sesión 22

workbox-config.js
module.exports = {
  globDirectory: '.',
  globPatterns: ['index.html', 'manifest.json', 'css/*.css', '*.js', 'icons/*.png'],
  globIgnores: ['node_modules/**/*', 'workbox-config.js', 'package*.json'],
  swDest: 'sw.js',
  runtimeCaching: [
    {
      urlPattern: /\/icons\//,
      handler: 'CacheFirst',
      options: { cacheName: 'imagenes', expiration: { maxEntries: 60, maxAgeSeconds: 30*24*60*60 } },
    },
    { urlPattern: /\/api\//, handler: 'NetworkFirst', options: { cacheName: 'api-tareas' } },
  ],
};

SECCIÓN 05

UX/UI en PWAs

Un diseño efectivo no solo es atractivo: también debe ser claro, organizado y consistente [4].

ConexiónInstalaciónCarga
UX/UI · 5.1

Tres patrones que no existen en un sitio tradicional

Indicador de conexión

Un banner simple ("Sin conexión — mostrando datos guardados") evita confundir datos frescos con datos en caché.

Prompt de instalación propio

Capturar beforeinstallprompt y mostrarlo con un botón propio da control sobre el momento y el diseño.

Feedback de carga

Un skeleton screen evita que la app se sienta "congelada" mientras responde el Service Worker.

UX/UI · 5.2

Capturar e instalar con un botón propio

app.js (prompt de instalación)
let deferredPrompt;
window.addEventListener('beforeinstallprompt', (e) => {
  e.preventDefault();
  deferredPrompt = e;
  btnInstalar.hidden = false;
});
btnInstalar.addEventListener('click', async () => {
  deferredPrompt.prompt();
  const { outcome } = await deferredPrompt.userChoice;
  deferredPrompt = null;
});
Nota de compatibilidad: en Safari/iOS este evento nunca se dispara — ahí la única opción es instruir al usuario ("Toca Compartir → Añadir a inicio").

Resumen de la sesión

  • La compatibilidad real depende del navegador: Chrome y Edge dan soporte completo, Safari/iOS tiene limitaciones en instalación y actualización.
  • Workbox encapsula en módulos (routing, strategies, precaching, expiration, window) el trabajo escrito a mano en las Sesiones 17-21 — y workbox-precaching genera la lista de precaché por hash de contenido.
  • GenerateSW automatiza todo el sw.js — lo corrimos de verdad: 10 archivos, 25.9 kB. InjectManifest da control total cuando hace falta lógica propia (push, sync), como en la Sesión 26.
  • Una buena UX de PWA avisa cuándo se está offline, ofrece un prompt de instalación propio, y da feedback de carga.
  • Lighthouse audita Performance, Accessibility, Best Practices y SEO, con el checklist de instalabilidad de una PWA — y una auditoría real sirve para encontrar mejoras concretas.
  • El Gestor de Tareas automatiza su Service Worker y queda auditado hoy, pero el Sub-bloque A no cierra todavía: faltan las APIs de dispositivo y las notificaciones push (Sesiones 24-26).
